Retrieval pipeline (SWAG + CRAG)

Single Qdrant index. SWAG semantic metadata on each chunk reranks candidates before CRAG filtering. Shared by ingestion /rag/search, UI Search tab, and agent rag_search (default swag_crag). UI supports mode comparison: baseline · swag · crag · swag_crag. 

flowchart LR
  Q[Query] --> R[Vector retrieve Qdrant]
  R --> S[SWAG rerank Haiku profile]
  S --> G[CRAG Haiku grader]
  G -->|relevant| F[Filter and return chunks]
  G -->|ambiguous| RW[Rewrite query]
  RW --> R
  G -->|irrelevant| W[Tavily web fallback]
  W --> F
  F --> A[Researcher or UI]

Research run sequence

UI gateway parses LangGraph SSE and streams node progress. Researchers call ingestion SWAG+CRAG (not raw Qdrant); traces go to LangSmith.

Document ingestion sequence

Upload capped at 100 MB; rate limited at the API gateway. Indexing stores vectors and SWAG semantic metadata on each chunk in one pass.

Security controls

ControlImplementation
Edge authCognito @ ALB when ACM cert ISSUED; NLB has no auth until then
TLSACM cert for langrag.automatico.llc (pending GoDaddy DNS validation)
IAMIRSA: agents → Sonnet 4.6 + Titan embed; ingestion → Titan embed + Haiku SWAG profiles + CRAG grader
SecretsAWS Secrets Manager + K8s app-secrets (LangSmith, S3 bucket)
Upload cap100 MB on UI gateway + ingestion
Rate limits10 ingest / 5 research per min per client IP
SSRFURL ingest blocks private IPs, metadata, bad redirects
NetworkNetworkPolicies: UI → agents/ingestion only
SpendAWS Budget email alerts on Bedrock (80% / 100%)
